# createRoot 方法

* createContainer 方法
  * const root = createFiberRoot()
    * const root = new FiberRootNode()，得到 FiberRootNode 实例，即 React 应用实例，上面存放了很多应用级别的数据
    * const uninitializedFiber = createHostRootFiber()，得到 React 应用挂载 DOM 对应的 FiberNode 实例，核心方法就是 createFiber 方法，实例上存放了很多 Fiber 节点相关的数据
    * root.current = uninitializedFiber
    * uninitializedFiber.stateNode = root，fiberNodeIns.stateNode 正常来说指向的都是对应的 DOM 节点，但 HostRootFiber 实例的 stateNode 指向的是节点所在 React 应用的实例
    * 设置 uninitializedFiber.memoizedState 和 uninitializedFiber.updateQueue
    * return root
    
    > 这样就形成了一个 React 应用的初始结构，ReactFiberRoot.current = HostFiberRoot，HostFiberRoot.stateNode = ReactFiberRoot
  
* markContainerAsRoot，给当前容器节点打标记，即 dom 节点上存储 hostFiberRoot 实例，建立 DOM 节点到 Fiber 节点的映射关系

* listenToAllSupportedEvents，事件委托机制
  * 遍历所有事件，通过 listenToNativeEvent 方法为 React 应用挂载点设置事件监听器
    * 对于可以委托的事件，在冒泡阶段注册事件监听器
    * 为所有事件在捕获阶段注册事件监听器
    * 特殊处理 selectChange 事件，在 document 上注册一个在冒泡阶段的事件监听器
  * listenToNativeEvent，调用 addTrappedEventListener 方法
  * addTrappedEventListener
    * let listener = createEventListenerWrapperWithPriority()，创建具有 React 优先级的事件监听器
      * const eventPriority = getEventPriority(domEventName)，不同 DOM 事件对应不同的 React 事件优先级，最终执行的都是 dispatchEvent 方法
      * dispatchEvent 方法，当 DOM 事件被触发后，执行的就是该方法
        * dispatchEventForPluginEventSystem，核心逻辑是执行 batchedUpdates 方法
        * batchedUpdates 方法的逻辑就是直接执行 dispatchEventsForPlugins
      * dispatchEventsForPlugins，从触发事件的 Fiber 节点开始，沿着 Fiber Tree 向上查找，找到所有和当前事件类型和阶段匹配的事件监听器，然后按照顺序依次执行
    * 根据不同情况，执行不同的逻辑，核心就是 rootDom.addEventListener(eventName, listener, options | boolean)

* return new ReactDOMRoot()，ins._internalRoot = root，ins 上有 render 和 unmount 方法
